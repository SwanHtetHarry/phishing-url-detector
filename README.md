# AI Phishing URL Detector

An AI-powered phishing URL detection application built with **Python, Scikit-learn, Streamlit, Random Forest, and the VirusTotal API**.

The application analyzes the structure of a submitted URL using a trained machine-learning model and combines the prediction with VirusTotal reputation information to provide a more informative security assessment.

---
## Live Demo

Try the deployed application here:

[Open AI Phishing URL Detector](https://phishing-url-detector-4cpuehf9qsdxeuwtvzypt4.streamlit.app)

## Features

- Detects phishing-like and legitimate-like URLs using Machine Learning
- Uses a trained Random Forest classifier
- Automatically extracts URL characteristics
- Displays model prediction confidence
- Checks existing VirusTotal reputation reports
- Shows malicious, suspicious, harmless, and undetected results
- Supports optional fresh VirusTotal scans
- Provides an Overall Risk Assessment
- Keeps the VirusTotal API key outside the source code
- ML analysis does not visit the submitted website
- Includes warnings for sensitive/private URL submissions

## Classification Labels

The project uses the following target labels:

```text
0 = Phishing
1 = Legitimate
```

Because phishing is represented by `0`, phishing recall was specifically calculated using the phishing class as the target class.

---

## Models Tested

Three machine-learning classification algorithms were evaluated using the deployment-ready URL features.

| Model | Accuracy | Phishing Precision | Phishing Recall | Phishing F1 |
|---|---:|---:|---:|---:|
| Logistic Regression | 99.316% | 99.945% | 98.453% | 99.193% |
| Decision Tree | 99.520% | 99.775% | 99.100% | 99.436% |
| **Random Forest** | **99.526%** | 99.760% | **99.130%** | **99.444%** |

Random Forest was selected as the final model because it achieved the highest phishing recall and strongest overall performance for the deployment-ready pipeline.

---

## 5-Fold Cross-Validation

The models were also evaluated using 5-fold stratified cross-validation.

| Model | Mean Phishing Recall | Standard Deviation |
|---|---:|---:|
| Logistic Regression | 98.492% | 0.000602 |
| Decision Tree | 99.061% | 0.000645 |
| **Random Forest** | **99.097%** | 0.000701 |

Random Forest again achieved the highest average phishing recall.

---

## Why Phishing Recall Matters

For this project, phishing recall is especially important.

A phishing URL incorrectly predicted as legitimate can be more dangerous than a legitimate URL incorrectly flagged as phishing.

Example:

```text
Actual URL: Phishing
Model Prediction: Legitimate
```

This type of error could cause a user to trust a malicious URL.

Therefore, minimizing missed phishing URLs was one of the main priorities when selecting the final model.

## Feature Importance

Random Forest feature-importance analysis showed that several URL characteristics were particularly useful for classification.

Important features included:

- HTTPS usage
- Number of other special characters
- Number of digits
- Letter ratio
- Digit ratio
- URL length

Feature importance does not mean that a feature alone determines whether a URL is phishing. It only indicates how useful that feature was to the trained Random Forest model.

## VirusTotal Integration

The application integrates the **VirusTotal API** as an additional source of security information.

After the machine-learning model analyzes a URL, the application can retrieve an existing VirusTotal report.

The interface displays:

- Malicious detections
- Suspicious detections
- Harmless results
- Undetected results

Example:

```text
VirusTotal Reputation

Malicious:   0
Suspicious:  0
Harmless:   63
Undetected: 27
```

A VirusTotal result is treated as additional evidence rather than an absolute guarantee of safety.

---

## Fresh VirusTotal Scan

The application also provides an optional:

```text
Run Fresh VirusTotal Scan
```

feature.

When the user chooses this option, the URL is submitted to VirusTotal for a new analysis.

The application can then display:

- Scan completion status
- Malicious detections
- Suspicious detections
- Harmless results
- Undetected results

Technical information such as the VirusTotal Analysis ID and analysis status is available through an expandable **Technical scan details** section.

> **Privacy Warning:** A fresh scan sends the submitted URL to VirusTotal. Private, internal, confidential, or sensitive URLs should not be submitted.

---

## Overall Risk Assessment

The application combines the ML prediction with VirusTotal reputation information.

Example:

```text
Machine Learning:
Legitimate-like URL
Confidence: 99.79%

VirusTotal:
Malicious: 0
Suspicious: 0

Overall Assessment:
No strong malicious indicators found.
```

The assessment logic works as follows:

- VirusTotal malicious detections → **High Risk**
- VirusTotal suspicious detections → **Suspicious**
- ML predicts phishing-like while VirusTotal reports no malicious detections → **Caution**
- ML predicts legitimate-like and VirusTotal reports no malicious or suspicious detections → **No strong malicious indicators found**

The application intentionally avoids saying that a website is completely "safe."

## Dataset Bias and Model Behavior

During development, HTTPS usage was found to have a strong relationship with legitimate URLs in the training dataset.

For example, the model could behave differently for:

```text
http://www.google.com
```

and:

```text
https://www.google.com
```

This demonstrates that a machine-learning model can learn patterns that are strongly represented in its training dataset.

Removing the HTTPS feature was tested, but the model's overall performance and phishing recall decreased.

Because of this limitation, the application describes predictions as:

```text
Phishing-like URL
```

and:

```text
Legitimate-like URL
```

instead of claiming that a URL is definitely phishing or definitely safe.

## Security and Privacy

The ML component analyzes the URL string and does not visit the submitted website.

However, the optional VirusTotal fresh-scan feature sends the URL to VirusTotal.

Users should avoid submitting URLs containing:

- Authentication tokens
- Passwords
- Private internal resources
- Confidential information
- Password-reset links
- Session IDs
- Sensitive query parameters
- Internal company URLs

---

## Limitations

This project has several limitations:

- The ML model was trained using a specific phishing URL dataset.
- Real-world phishing techniques continuously evolve.
- The model can produce false positives.
- The model can produce false negatives.
- URL structure alone cannot detect every phishing attack.
- VirusTotal may not have information about newly created URLs.
- Zero VirusTotal detections do not guarantee that a website is safe.
- The application does not currently inspect complete webpage content.
- Domain age is not currently analyzed.
- DNS reputation is not currently analyzed.
- SSL certificate details are not currently analyzed.
- Model confidence should not be interpreted as a guaranteed real-world probability of safety.
